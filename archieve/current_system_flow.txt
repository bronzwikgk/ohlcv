6. Mine base entry rule per symbol

The system creates entry cases from the data.

Each case means:

today's derivative features -> future target result

Then it mines feature conditions such as:

close_to_ema_3_pct >= X
EMA volatility >= Y
volume_to_ema_21_pct <= Z

The system rejects rules that are too broad or not better than baseline.

A mined base candidate must have:

enough matches
positive average return
win-rate lift over symbol baseline
not too much dataset coverage

The system ranks base candidates by useful occurrence:

win count
win-rate lift
average return
base score
dominant exit occurrence

9. Mine loss trades

The system looks at losing trades and finds derivative conditions that appear mostly in losses.

These become miss-avoid candidates.

Examples:

avoid weak volume
avoid overextended price
avoid unstable EMA trend
avoid negative short-term momentum


10. Mine hit cases

The system looks at strong target or hit cases and finds derivative conditions that appear before success.

These become hit-confirm candidates.

Examples:

require momentum
require volume strength
require positive EMA structure
require acceptable EMA volatility


11. Recursively optimize strategy

The optimizer creates child strategy versions.

It can add:

hit-confirm filters
miss-avoid filters
both hit-confirm and miss-avoid filters

Example:

AND hit-confirm condition
AND NOT miss condition

The optimizer tests combinations recursively up to the configured depth.

Current depth:
